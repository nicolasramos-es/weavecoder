## Hermes Workspace (`outsourc-e/hermes-workspace`)

Web-based multi-agent UI. Accessed from other devices on the LAN.

### Location

- **Repo:** `~/hermes-workspace/`
- **Installed via:** `curl -fsSL https://hermes-workspace.com/install.sh | bash -s -- workspace`
- **Started via:** `cd ~/hermes-workspace && pnpm start:all`
- **Log:** `/tmp/nrmusic_upload.log` (for embedded upload cron logs)

### Local Network Access

The workspace is configured with `HOST=0.0.0.0` in `.env.local` (not committed) so it's reachable from other devices on the LAN:

```env
PORT=3000
HOST=0.0.0.0
HERMES_PASSWORD=<auto-generated-32-char>
COOKIE_SECURE=0
```

- **Local:** `http://127.0.0.1:3000`
- **LAN:** `http://192.168.1.17:3000`
- **Auto-start:** NOT set up via launchd — started manually via `pnpm start:all`
- The embedded gateway starts inside the workspace's `start:all` script; it does NOT conflict with the system gateway because workspace reuses the existing one

### Swarm Workers

The workspace installs a semantic worker swarm defined in `swarm.yaml`. Roster: orchestrator, builder, reviewer, qa, researcher, ops-watch, maintainer, strategist, inbox-triage, km-agent.

### Password

Stored in `~/.local/share/hermes-workspace/.env.local` (DO NOT commit). Regenerate if compromised.

## Hermes WebUI (`nesquena/hermes-webui`)

The primary web interface. Replaces the old dashboard (0.0.0.0:9119).

### Location

- **Repo:** `~/.hermes-webui/`
- **Log:** `~/.hermes/webui.log` (bootstrap) + `/tmp/hermes-webui-launchd.log` (service)

### Manual Commands

```bash
cd ~/.hermes-webui

# Start foreground (dev)
python3 bootstrap.py --no-browser

# Start foreground with LAN access
HERMES_WEBUI_HOST=0.0.0.0 HERMES_WEBUI_PASSWORD=hermes2026 python3 bootstrap.py --no-browser

# Background daemon (ctl.sh)
HERMES_WEBUI_HOST=0.0.0.0 HERMES_WEBUI_PASSWORD=hermes2026 ./ctl.sh start
./ctl.sh status
./ctl.sh stop
./ctl.sh restart
./ctl.sh logs --lines 100

# launchd service control
launchctl load ~/Library/LaunchAgents/com.hermes.webui.plist
launchctl unload ~/Library/LaunchAgents/com.hermes.webui.plist
launchctl list | grep hermes
```

### Config File

`~/.hermes-webui/.env`:
```
HERMES_WEBUI_HOST=0.0.0.0
HERMES_WEBUI_PORT=8787
HERMES_WEBUI_PASSWORD=hermes2026
```

### URL

- **Remoto (desde MacBook):** `http://192.168.1.17:8787`
- **Local:** `http://127.0.0.1:8787`

### WebUI Features

- Three-panel layout: sessions sidebar, chat center, workspace file browser right
- Hermes Control Center (settings, models, profiles, cron, skills, themes)
- Password auth, light/dark themes, multi-profile support
- Workspace file browsing with inline preview
- Full CLI parity via web

## Troubleshooting

### WebUI won't start

```bash
# Check port conflict
lsof -i :8787

# Check launchd status
launchctl list | grep hermes.webui
# Exit code 0 = running, non-zero = failed

# Check logs
cat /tmp/hermes-webui-launchd.log
tail -50 ~/.hermes/webui.log

# Rebuild venv if dependencies changed
cd ~/.hermes-webui && rm -rf venv && python3 bootstrap.py --no-browser
```

### launchd plist failed to load

Common causes:
- **Port already in use** — kill the old process first
- **Path mismatch** — the plist at `~/Library/LaunchAgents/com.hermes.webui.plist` hardcodes the bootstrap path. Verify it exists
- **Wrong python path** — ensure `PATH` env var in the plist includes the Hermes venv

### Gateway not running

The gateway (`ai.hermes.gateway`) is managed separately by Hermes itself, not by our launchd plists. To restart:
```bash
hermes gateway restart
hermes gateway status
```
